# 09 · UI and UX

Feels like Slack or Discord with mouse and keyboard. LazyVim keys sit on top of everything, so the app is fully navigable without the mouse. Colours come from the theme (`12-settings-theme-onboarding.md`). The maintainer will request visual changes later; build layout and behaviour, keep styling in theme tokens.

## Design reference

The look comes from `docs/design/` (made from the concept demo): `tokens.json` (colours, spacing, radii, type, shadows, keycap style), `components.md` (one entry per component: layout, states, tokens) and `reference/` (screenshots per component, light and dark). Build every component to its entry there. UI features attach WebDriver screenshots of each state as evidence (`14-quality.md#evidence`), and the reviewer compares them with the matching reference crop. Per-OS screenshot baselines start after the walking skeleton; only the maintainer approves a baseline change.

## Layout

```
│ rail │ sidebar        │ buffer tabs                   │ right panel      │
│ (S)  │ STAT 311       │ Slide 3 · Properties          │ Doubts · Sources │

│      │ Lists …        │ │ keycaps on selection   │    │                  │
│      │ Sources …      │ └────────────────────────┘    │                  │
├──────┴────────────────┴───────────────────────────────┴──────────────────┤
│ hint bar: s steps · a ask · D doubt · K define · o note · mm flag · ␣ more│

                                             keystroke overlay: [␣ a s]
```

- **Course rail** (Discord servers): one icon per course, `+` to add, drag to reorder. `Ctrl/Cmd-1…9` jumps to a course.
- **Sidebar** (Discord channels / neo-tree): Dashboard; Lectures (date and open-item badges); Lists (Doubts, Flags, Office hours, Later, Revise); Sources. Toggle with `␣e`.
- **Buffer**: the lecture or dashboard; buffer tabs on top (bufferline).
- **Right panel**: Doubts, Sources (with parse report), AI activity (running jobs, usage). Toggle `␣r`. v1 adds Transcript.
- **Status line** (lualine): mode, course/lecture, slide, active model, lecture cost, job spinner.

## Slack and Discord behaviours

- Hover a gloss, list row or sidebar item → hover action buttons.
- Right-click anything → context menu listing every command for that element with its key.
- Glosses are messages: follow-ups are threads under them, folded to "3 replies".
- `Ctrl/Cmd-K` quick switcher (courses, lectures, lists, sources). `Ctrl/Cmd-Shift-P` command palette (every command, with keys).
- Arrow keys, `Enter`, `Esc`, `Tab` work in every list and dialog. Vim keys work there too (`j`/`k`, `/` filter, `gg`/`G`).
- Drag and drop: files onto the rail (new course), onto `slides/` or `sources/` in the sidebar, or onto a lecture (link slides).

## Keycap buttons

When a gloss is selected (cursor on it or clicked), a row of raised, keycap-style buttons appears along its top edge, one per available key: `r` Regenerate, `R` With feedback, `zg` Good, `zw` Wrong, `^A` More, `^X` Less, `i` Edit, `↵` Reply, `dd` Delete, `za` Fold. Buttons look like physical keys (3D, with a bottom edge) and visibly press down when clicked or when that key is typed. The same component is used for slide-line actions in the hint bar.

## Hint bar and keystroke overlay

- The hint bar (above the status line) lists the keys that work now: it changes with the cursor's element (slide line, gloss, note, dashboard row) and the mode. Pressing `␣` opens which-key with all groups after 300 ms.
- Detail level follows onboarding ("Daily · a little · never" Vim use); "never" shows the mouse action next to each key.
- The keystroke overlay (bottom right of the buffer) shows typed keys, including pending sequences, fading after 1.5 s. On by default for new users.
- Read mode (`␣ur`, `:read`) hides rail, sidebar, hint bar and overlay.

## Editing

- Single click moves the cursor. Double-click on any editable text (own notes, glosses, parsed slide lines) enters insert mode at that point. `Esc` returns to normal mode.
- Mouse selection shows a small toolbar: Ask, Explain, Flag, Copy.
- Slide lines and glosses are read-only in normal mode: single-letter keys are commands there. `i` (or double-click) makes them editable; edited glosses get `by=you+ai`, edited slide lines save the fix as the parse correction.

## Prompt row

Opens under the anchored block after `a`, `D`, `>`, `R`, `v…a` or Reply.

- `Tab` toggles where the answer goes: **into this gloss** (threaded reply) or **new gloss**. Shown as a two-way toggle beside the input; the default is "new gloss" on slide lines and "into this gloss" when the cursor is on a gloss.
- `↵` sends. `Shift-↵` new line. `Esc` cancels (and cancels a running stream).
- `@` opens mentions: `@slide4`, `@L06`, `@source-name`, `@model-name`, `@web`, `@noweb`.
- Buttons: model picker, web search toggle (globe), figure mode (auto/ask/off).
- `↑` / `↓` recall previous prompts.

## Accessibility

All controls are reachable by keyboard and have accessible names. Respect reduced motion (keycap press and overlay fade become instant). Minimum contrast follows the theme; amber confidence borders also carry a text badge.
